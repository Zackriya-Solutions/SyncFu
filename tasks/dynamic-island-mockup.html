Dynamic Island notification

A pure-black capsule anchored to the top-center notch that spring-morphs into a full notification card. One island engine drives every panel below: the concave-shoulder notchPath is drawn as an inline SVG whose d is recomputed each animation frame from a damped-spring tween on width, height and the two corner radii – the outer box is never resized on a timeline. Same content, actions, progress and 27 style overrides as today's glass card; a different shape and anchor. Visual spec for approval, not production code.

Anchor: top-center (hugs the macOS notch; floats on Windows/Linux) Compact = hardware-black normal low high critical

How the three trade off

        
Same payload of N notifications, judged on the axes that matter for an always-on overlay.

        
ModelSpace useGlanceabilityPractical max NInteraction costUsed by

          
            
ABadge + cycleConstant – one pill, alwaysOne item at a glance; rest hidden∞ (badge caps 9+)High – click + cycle N−1 to read allopen-island, open-vibe (closed spotlight)

            
BRanked listrecCompact closed; ~360px tall openAll items ranked in one open glance∞ (6 rows then scroll)Low – one click reveals everythingPillar (open state), open-island list

            
CStack underGrows with N – eats the screenAll visible… until they collide~4 before crowdingLow to read, but occludes desktopNone (anti-pattern)

          

        
Verdict: Model B is the research consensus – both island apps and Pillar's open state converge on one spotlight + count → ranked, deduped, capped-then-scroll list. Model A is a valid fallback where vertical space is scarce. Model C is an honest counter-example: stacking toasts is the one thing no mature app does. Priority timeouts (low 6s / normal 8s / high 12s / critical never) and the absorb-upward dismiss (y:-40, scale:.4, spring 300/25) are shared across all three.

🔒 Hidden during screen sharing

          
The island window is excluded from capture at the OS level – never painted into a recording or share. This is one window property per platform:

          
    
            
  • macOS: NSWindow.sharingType = .none – NotchPrompter PrompterWindow.swift → updateScreenRecordingVisibility(), wired via Combine, default ON.
    • 
            
  • Windows: SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE) (Win10 2004+).
    • 
            
  • Cross-platform: Tauri v2 window.set_content_protected(true) maps to both of the above.
    • 
            
  • Linux: no reliable equivalent – documented limitation (fallback: auto-hide while a capture app is frontmost).
    • 
          

          
⚠ open-island and open-vibe set sharingType = .readOnly, leaving their overlays capturable in screen shares. That is a mistake syncfu must not copy – default to hidden.
